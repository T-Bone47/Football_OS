# Action-Value Methodology & Foundation — Football Intelligence OS

## 1. Overview & Architecture

The Action-Value Foundation in Football Intelligence OS formalizes the value generated by individual player actions during matches.

```
Action (Canonical) ──> Context (Temporal/Positional) ──> State Representation ──> Value Model ──> Action Value Output
```

Two complementary model families are structured under `app.action_value`:
1. **Deterministic Action Impact Model (`ActionImpactModel`)**:
   - Evaluates observable, discrete match performance metrics.
   - Requires zero spatial coordinates, operating on verified Bronze and Silver events.
   - Provides a stable, explainable baseline for net action value per 90 minutes.
2. **Spatial Threat Transition Model (`SpatialThreatModel`)**:
   - Represents pitch states via spatial discretization ($16 \times 12$ pitch grid).
   - Designed to evaluate possession progression and dangerous zone entries.
   - **Gated by Data Sufficiency**: If coordinate tracking data is unavailable or $<80\%$, strictly halts and returns `INSUFFICIENT_DATA`.

## 2. Action Impact Model (Baseline Methodology)

### 2.1 Empirical Weights
Each discrete action receives an empirical weight calibrated to match outcomes and event risk:

| Action Subtype | Weight | Rationale |
| :--- | :--- | :--- |
| `GOAL` | $+1.00$ | Ultimate positive outcome |
| `ASSIST` | $+0.80$ | Direct primary chance completion |
| `PENALTY_GOAL` | $+0.75$ | High-probability conversion |
| `SAVE` | $+0.35$ | Prevents opposition goal |
| `KEY_PASS` | $+0.25$ | Primary creation event |
| `SHOT_ON_TARGET` | $+0.20$ | Threat creation requiring keeper intervention |
| `TACKLE` | $+0.15$ | Turnover generation |
| `INTERCEPTION` | $+0.15$ | Opposition possession termination |
| `BLOCK` | $+0.12$ | Shot/pass deflection in defensive zone |
| `DRIBBLE_SUCCESS` | $+0.12$ | 1v1 line-breaking progression |
| `PASS_COMPLETED` | $+0.02$ | Incremental retention and possession value |
| `FOUL_DRAWN` | $+0.06$ | Dead-ball territory win |
| `PASS_INCOMPLETE` | $-0.02$ | Turnover risk |
| `DUEL_LOST` | $-0.05$ | Loss of territorial contest |
| `FOUL_COMMITTED` | $-0.08$ | Set-piece concession |
| `YELLOW_CARD` | $-0.30$ | Disciplinary liability & tactical restriction |
| `GOAL_CONCEDED` | $-0.85$ | Concession liability for defensive unit |
| `RED_CARD` | $-1.00$ | Severe competitive disadvantage |

### 2.2 Formulation
$$\text{Net Action Impact} = \sum_{a \in \text{actions}} w(a) \times \text{qty}(a)$$
$$\text{Impact Per 90} = \frac{\text{Net Action Impact} \times 90.0}{\text{Minutes}}$$

## 3. Spatial Threat Model (Data Sufficiency Hard Gate)

### 3.1 Hard Gate Policy
A spatial threat model requires granular $(x, y)$ tracking or high-frequency event stream coordinates for passes, carries, and tackles. 
Synthesizing or hallucinating coordinates when a provider omits them violates Non-Negotiable Principle 1 (**NO FABRICATION**).

Therefore:
```python
if spatial_coverage < 0.80:
    return ActionValueResult(
        status="INSUFFICIENT_DATA",
        spatial_data_sufficient=False,
        data_limitation_reason=(
            f"Provider event stream provides {spatial_coverage*100:.1f}% spatial coordinate coverage. "
            f"Granular (x, y) pitch coordinates are required for spatial threat modeling without synthetic bias."
        ),
        licensing_requirements=[
            "Opta F24 Event Stream with (x, y) coordinates",
            "StatsBomb 360 Event Stream",
            "Wyscout Event Data v3 with spatial coordinates",
        ],
    )
```
