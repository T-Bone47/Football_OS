# Phase 14 — Cryptographically Traceable Evidence Graph V3

**Certified Baseline**: Phase 13 — `DECISION_SIMULATION_VALIDATED`  
**Current Phase**: Phase 14 — `OUTCOME_AWARE_DECISION_INTELLIGENCE`  
**Core Lineage Rule**: Every decision, scenario, outcome, and institutional learning signal is connected in a cryptographically traceable Directed Acyclic Graph (DAG) with a deterministic SHA-256 audit digest.

### 2. Node & Edge Type Definitions

#### Node Types (10 Canonical Entities)
1. `DATA`: Bronze provider match feeds, event streams, financial filings (`OBSERVED`).
2. `FEATURE`: Normalized intelligence vectors, action values, role archetypes (`MODELLED`).
3. `MODEL`: Versioned predictive, calibration, or valuation models (`MODELLED`).
4. `PREDICTION`: Concrete forecast output generated by an intelligence model (`MODELLED`).
5. `ASSUMPTION`: Stated parameter priors and scenario framing (`ASSUMPTION`).
6. `SCENARIO`: Simulated transfer window, formation change, or squad alternative (`SCENARIO`).
7. `DECISION`: Final executive action recorded by the recruitment room (`SCENARIO`).
8. `OUTCOME`: Real-world empirical observation from the Outcome Ledger (`OBSERVED`).
9. `EVALUATION`: Structured delta and tolerance audit comparing expectation vs realization (`ANALYSIS`).
10. `LEARNING_SIGNAL`: Institutional signal triggering monitoring or challenger review (`ANALYSIS`).

#### Edge Types (10 Directed Connectors)
- `DERIVED_FROM`: Feature from data, prediction from model.
- `USED_BY`: Model consuming feature, scenario consuming prediction.
- `ASSUMED_BY`: Scenario depending on an explicit parameter assumption.
- `SIMULATED_BY`: Scenario produced by multiple predictive models.
- `DECIDED_BY`: Decision finalizing a specific simulated scenario.
- `REALIZED_AS`: Real-world outcome materializing following a decision.
- `EVALUATED_BY`: Outcome ingested by an evaluation report.
- `TRIGGERED`: Divergence triggering a learning signal.
- `SUPPORTED_BY`: Empirical evidence confirming an analytical thesis.
- `CONTRADICTED_BY`: Empirical evidence refuting a scenario hypothesis.

### 3. Cryptographic Integrity & Digest Calculation

To prevent post-hoc graph manipulation:
- Nodes and edges are serialized in deterministic lexical key order.
- A cryptographic SHA-256 digest is generated over the complete topology.
- Replaying the graph with identical nodes and edges produces the exact same 64-character hash digest.
